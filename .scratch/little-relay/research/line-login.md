# LINE Login 身分與部署事實

查證日期：2026-10-05。來源均為 LINE Developers 官方文件；以下是技術前提，未決定店主的核准操作流程。

## 身分邊界

- 顧客的穩定鍵是 LINE **user ID**：同一 provider 下各 LINE Login／Messaging API channel 對同一人給出相同 ID；不同 provider 給出不同 ID。LINE 指出 user ID 不會變，但顯示名稱、頭像與狀態訊息可由使用者變更，不能當身分鍵。Channel 建立後不能移到另一 provider。跨服務共用資料另受 LINE User Data Policy 限制，不能只憑技術上相同的 ID 推定可以共用。[LINE：Get user IDs](https://developers.line.biz/en/docs/messaging-api/getting-user-ids/)；[LINE：Managing users](https://developers.line.biz/en/docs/line-login/managing-users/)；[LINE：Getting started](https://developers.line.biz/en/docs/line-login/getting-started/)；[LINE：Provider design basics](https://developers.line.biz/en/tips/2026/06/25/provider-design-basics/)
- LINE Login 取得 user ID 以使用者登入並同意授權為前提。因此，首次登入／同意前，商店不能從 LINE Login 可靠地預知某位顧客的 provider-scoped ID；用顯示名稱或自填資訊預先對應帳號沒有官方身分保證。`openid` 可在經驗證的 ID token `sub` 取得 ID；`profile` 可用 access token 讀取 user ID。電子郵件需額外申請權限及請求 `email` scope，不能假設每位顧客都有可取得的 email。[LINE：Managing authorized apps](https://developers.line.biz/en/docs/line-login/managing-authorized-apps/)；[LINE：Integrating web login](https://developers.line.biz/en/docs/line-login/integrate-line-login/)；[LINE：API reference](https://developers.line.biz/en/reference/line-login/)

## 網頁登入與伺服器驗證

- 網頁流程是 OAuth 2.0 authorization code／OpenID Connect：先在 channel 登記 callback URL；導向 `https://access.line.me/oauth2/v2.1/authorize`，帶 channel ID、註冊的 redirect URI、scope 與每次登入隨機產生的 `state`；callback 收到 code 與 state 後，先比對 state，再由後端以 code、redirect URI、channel ID／secret 換 token。Code 僅能使用一次，有效 10 分鐘；channel secret 是機密，應只留在伺服器設定。[LINE：Integrating web login](https://developers.line.biz/en/docs/line-login/integrate-line-login/)；[LINE：Security checklist](https://developers.line.biz/en/docs/line-login/security-checklist/)
- 若使用 `openid`，每次授權可帶 `nonce` 以防重播，驗證 ID token 時一併提交預期的 `client_id` 與 `nonce` 至 `POST /oauth2/v2.1/verify`；成功回應的 `sub` 才是 user ID。LINE 明示 ID token 可被偽造，不能直接信任客戶端解碼結果。若採 access token 路徑，後端須驗證 token、檢查回應 `client_id` 等於本站 channel ID 且 `expires_in` 為正，再由 LINE profile API 取得 user ID；不要信任客戶端直接傳來的 ID／profile。[LINE：API reference](https://developers.line.biz/en/reference/line-login/)；[LINE：Secure login process](https://developers.line.biz/en/docs/line-login/secure-login-process/)
- LINE 支援並建議 PKCE：每次登入產生 `code_verifier`，授權請求傳 `S256` 的 `code_challenge`，換 token 時傳原 verifier，以降低授權碼遭攔截的風險。`state`、`nonce`、PKCE 各保護不同環節，不能互相替代。[LINE：PKCE support](https://developers.line.biz/en/docs/line-login/integrate-pkce/)；[LINE：Integrating web login](https://developers.line.biz/en/docs/line-login/integrate-line-login/)

## 首次登入、撤銷與新店設定

- 新建 LINE Login channel 預設為 **Developing**；只有具該 channel Admin 或 Tester 角色且 LINE 帳號已連結的開發者可測試。正式顧客要登入，channel 必須設為 **Published**。這是 LINE 的 channel 測試名單，與商店自己的顧客允許名單／核准狀態是兩個不同邊界；後者只能在成功驗證 LINE 身分後以已取得的 user ID 套用。[LINE：Console overview](https://developers.line.biz/en/docs/line-developers-console/overview/)；[LINE：Getting started](https://developers.line.biz/en/docs/line-login/getting-started/)；[LINE：Secure login process](https://developers.line.biz/en/docs/line-login/secure-login-process/)
- 使用者可在 LINE 撤銷授權；撤銷會立即使 access／refresh token 失效，重新登入須重新同意，但同 provider 的 user ID 不變。LINE 的開發準則另要求：使用者從服務註銷或解除連結時，服務應呼叫 deauthorize API 並告知使用者會發生的事；單純 revoke access token 與 deauthorize 授權是不同 API。[LINE：Managing authorized apps](https://developers.line.biz/en/docs/line-login/managing-authorized-apps/)；[LINE：Development guidelines](https://developers.line.biz/en/docs/line-login/development-guidelines/)；[LINE：API reference](https://developers.line.biz/en/reference/line-login/)
- 複製到另一商店時，先決定 provider 歸屬與是否為獨立 app／channel；LINE 要求每個 app 建自己的 LINE Login channel，且 channel 無法事後移轉 provider。若新店採獨立 channel，須在 LINE Developers Console 建 channel、登記該店 callback URL、設定／保管**該 channel** 的 ID 與 secret，完成測試後發布，並按需要另行申請 email 權限。不能直接沿用舊店 channel 的憑證或假設跨 provider user ID 相同。若刻意共用同一 channel，LINE 可登記多個 callback URL，但同一 channel 的身分／同意邊界也將共用；這是部署設計選擇，並非官方要求每店必有不同 provider。[LINE：Getting started](https://developers.line.biz/en/docs/line-login/getting-started/)；[LINE：Integrating web login](https://developers.line.biz/en/docs/line-login/integrate-line-login/)；[LINE：Console overview](https://developers.line.biz/en/docs/line-developers-console/overview/)
