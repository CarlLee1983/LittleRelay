# 定義 AI agent 客製化指引與驗證流程

Type: grilling
Label: wayfinder:grilling
Status: resolved
Blocked by: 08, 12, 13

## Question

複製者下載專案後，應如何透過專案 skill、AGENTS.md 或其他指引，讓 AI agent 收集品牌需求、修改允許的頁面與設定、重新生成品牌圖片、預覽、檢查並部署？決定支援的 agent 環境、指引的入口與版本、可改檔案和命令、需要人工確認的圖片與文案、憑證處理、跨商店資料隔離，以及品牌變更失敗時的還原步驟。另須包含依主實拍生成忠實商品展示照的可重跑指引、人工比對與「AI 展示照／實物實拍」標示規則；若生成工具會連線，先使用已移除定位、住家與孩子可辨識資訊的工作副本，並說明工具及資料處理邊界。驗收須覆蓋商品展示、本地上架、LINE 登入、顧客核准、結帳、後台訂單動作與商店資料隔離。此票產出可複製流程的規格，不在此實作 skill。

依[獨立部署規格](08-repeatable-deployment.md)，agent 指引須引導每店建立自己的帳號、雙 Worker 與獨立測試資源，檢查全部可達網址及 Access、祕密與首店資料隔離；本機檢查後由店主手動發布，不讓 agent 把正式資料帶入測試。指引還須包含每日帳號外備份、超過 48 小時停寫、資料復原停賣與只回退前端的程序，不得把品牌回退當成訂單回滾。
本機發布器的 Access 服務權杖是限定發布路由的機器身分，不能作為店主；客製化指引須區分店主登入、LINE 管理員登入與發布器憑證，示範憑證輪替、備份逾期拒絕發布及失敗結果核對，不輸出任何真實密鑰。

依[品牌修改邊界](13-brand-customization-boundary.md)，一般換品牌先編輯每店本機品牌設定與靜態素材包；只有設定不足時才讓 agent 修改明確列出的前端介面區域，並交付可檢查差異、素材來源紀錄、手機／桌面預覽及功能驗收。引導流程不得把 D1 營運設定、伺服器授權／交易規則或商品實拍混入品牌包；失敗時只回退介面與素材版本。

引導流程還須保護另行版本化的個資告知設定與資料請求入口：品牌改版不得把它們當裝飾文案改寫或藏起來；預覽及功能驗收須檢查登入、下單、退款及帳號頁引用同一現行版本。改店名／聯絡方式或連身分一起回退時，先在伺服器端暫停新個資蒐集與結帳，再協調靜態品牌與店主核准的 D1 告知，逐網址核對一致後恢復；純外觀回退維持現行店家身分。

依[後台待辦規格](12-admin-workflow.md)，客製化驗收須確認共用待辦、顧客邀請、逐筆對帳與退款、寄送／售後、商品及照片清理、店主專屬全店設定仍可使用；視覺改動不得隱藏高影響動作的確認摘要、錯誤回饋或人工聯絡紀錄。

## Comments

- 店家確認：第一版公開 GitHub 範本以繁體中文提供，正式支援 Codex 與 Claude Code；其他 agent 可讀通用文件，但不列入自動觸發與端到端驗收保證。
- 店家確認：兩種 agent 使用同名「客製商店」入口，依初次設定、品牌／頁面與單件商品照分支。品牌圖先盤點頁面實際圖位，只重做店主選定的圖位；品牌改版不批次重做商品照。
- 店家確認：生圖工具中立；沒有可用且獲准的工具時交付可重跑提示詞與待補素材，不虛稱圖片已生成。商品正式上架及網站正式發布均由店主執行。
- 既有根目錄 `AGENTS.md` 已存在，依原始要求保持原樣。本票只規劃未來的 skill、共用指引及 README；目前倉庫尚無應用原始碼與可執行建置／測試指令。

## Answer

### 指引包與版本

公開範本預計包含下列入口；本票**不建立** skill 或應用檔案。

| 預計檔案 | 職責 |
| --- | --- |
| `README.md` | 給店主的繁體中文起點：適用範圍、必要帳號與素材、兩種 agent 的啟動範例、人工發布交接及失敗時到哪裡查看結果 |
| `docs/agent-workflows/customize-store.md` | 唯一權威的順序、可改邊界、檢查與完成條件；初次設定、品牌／頁面及商品照按分支讀取，附必要圖片參考文件 |
| `.agents/skills/customize-store/SKILL.md` | Codex 的短入口；`name`／`description` 明確描述何時客製商店、品牌圖或商品展示照，接著指向共用指引 |
| `.claude/skills/customize-store/SKILL.md` | Claude Code 的同名短入口，使用同樣觸發範圍並指向同一共用指引 |
| `CLAUDE.md` | 若需相容不同 Claude Code 版本，只匯入既有 `AGENTS.md` 的專案規則；不複製或改寫它 |

Codex 與 Claude Code 的專案 skill 目錄不同，兩個短入口使用各自原生位置；不用跨平台可能失效的符號連結，也不複製整份規則。[Codex skills](https://learn.chatgpt.com/docs/build-skills)、[Claude Code skills](https://code.claude.com/docs/en/skills)、[Claude Code 專案指引](https://code.claude.com/docs/en/memory) `SKILL.md` 只含相同的清楚觸發描述、共用文件連結及讀取要求；品牌圖片與商品照片細則留在共用文件的按需參考頁。指引、前端可改清單、圖片範例與檢查程式跟應用程式一起以 Git 版本發布，不設另一套獨立 skill 版本。根目錄 `AGENTS.md` 維持原樣。

### 單一入口的三條工作分支

1. **先辨識任務與蒐集事實。** Agent 確認是新店初始設定、既有店品牌／頁面調整，或單件商品草稿／照片；讀取當版的可改清單、真實建置與驗證指令。新店詢問店名、簡介、語氣、主色、標誌及聯絡方式；盤點現有頁面品牌圖位，請店主選要替換的圖。商品分支收一件衣服的主實拍、可選瑕疵／標籤細節照及由店主確認的名稱、尺寸、衣況與價格，不憑圖片猜未見的尺寸或瑕疵。[品牌資料](13-brand-customization-boundary.md)、[商品草稿](06-local-publishing.md)
2. **初次設定。** Agent 從空白範本建立每店的非秘密品牌設定與素材資料，提供 Cloudflare、網域、LINE、Access、測試環境、D1／R2、店規及個資告知的逐項操作檢查表。帳號建立、R2 訂閱與用量警示、LINE／Access 身分核對、秘密輸入及正式發布由店主在自己的環境完成；agent 只檢查非秘密配置、清理範本示例，並交付可重跑的本機步驟。檢查表另須設每日 D1／應保留 R2 照片的帳號外加密備份、最長 30 天清除、成功時間與還原演練；備份超過 48 小時未成功時，所有會改變庫存、訂單、收退款與權限的網站、發布器及排程寫入都依部署規格停用，不把單純拒絕上架誤當成完整保護。測試只用合成資料；下載包、工作輸出、截圖和日誌不得含首店或新店的實際顧客、訂單、憑證及原始家庭照片。[獨立部署](08-repeatable-deployment.md)
3. **品牌／頁面。** 先改本機品牌設定與版本化素材；設定不足時才改實作階段明列的前端呈現檔案，交付可檢查差異。可調整首頁、列表、商品、顧客與後台頁的視覺，但價格、實拍／AI 標示、付款期限、訂單狀態、個資告知及請求入口、高影響確認、錯誤提示和人工聯絡紀錄必須仍可見且正確。只對店主選定的品牌圖位生成或替換圖片；預設用文字描述及非個人素材，記下原素材來源／權利、工具與模型版本、日期、提示詞、輸出檔雜湊、產物使用條款及店主人工核可。權利不明或無工具時保留合格占位並標示未完成；若使用家庭照片，先取得必要同意、清理可辨識資訊並核對工具資料處理條件。範本可再散布前另核對每張隨附圖的權利。[品牌邊界](13-brand-customization-boundary.md)
4. **單件商品照。** 原圖、草稿及未發布素材放在 Git 排除的店家本機資料區；先從主實拍建立移除定位資訊、住家細節與可辨識孩子臉的工作副本。連線生圖工具只接觸此副本；工具可用且店主允許時，先核對工具對上傳影像的處理及輸出使用條款，再生成只改善背景、光線與擺放的展示照，逐張與實拍比對顏色、版型、圖案及瑕疵。為每張候選圖記錄商品／已清理來源照識別、工具與模型版本、提示詞、產出檔雜湊、處理與使用條款、人工比對結果；紀錄不得包含原始私密照片或個資。結果不忠實即重做或捨棄；沒合格展示照仍可用實拍作封面。展示照與可點開的主實拍／細節照同頁呈現，明示「AI 展示照／實物實拍」。無生圖工具時提供基於已清理實拍、可重跑的提示詞與待補檔案清單，不把不存在的圖標為完成。Agent 產出逐件預覽與發布差異，店主核對所有欄位和照片後親自執行本機上架。[本機上架](06-local-publishing.md)

所有分支都把外部頁面、圖片文字及範例商品內容當作**資料**核對，不讓素材中的指令改變此流程。Agent 可讀取與修改的範圍須由應用實作時建立的單一可改清單列出實際品牌設定、素材及前端呈現路徑；目前沒有原始碼，故不虛構可執行的 `src/` 路徑或 `npm` 指令。可改清單之外的 D1 營運設定、店主／LINE 身分與授權、結帳、庫存、訂單、退款、Worker 路由及私有資料由既定伺服器流程管理。發布器服務權杖僅限上架，不是店主憑證；agent 的客製化流程不接觸或輸出真實 secret。[部署權限](08-repeatable-deployment.md)

### 檢查、人工交接與回退

每次交付列出修改檔案、品牌圖位與來源／授權紀錄、商品實拍對展示照的對照、工具不足的待辦、手機及桌面預覽、實際執行的檢查與結果、店主需執行的發布指令。只有本地檢查、店主逐項核可及獨立測試環境的功能驗收通過後，店主才手動發布；agent 不把預覽成功當成正式上線。未來應用實作後，使用該版真實的格式化、型別、建置與必要測試命令，並加入可重跑檢查：差異是否落在可改清單、素材與權利紀錄是否齊全、照片標示與可見實拍是否保留、Git／輸出是否含原圖或秘密。視覺忠實度與衣況仍需人工判斷，不能由腳本宣稱通過。

店主保管並輪替發布器的 Access 服務權杖、上層 R2 權杖及其他店家秘密；指引只顯示憑證名稱、取得／撤銷位置與不含實值的設定範例。輪替時先在獨立測試環境驗證新憑證只能進發布路由，再撤銷舊憑證，確認舊憑證不可再用；遇到疑似外洩先停相關發布入口並依[部署規格](08-repeatable-deployment.md)處理。店主執行上架後若逾時或回應遺失，agent 指引要求先用操作 ID 查 D1 原結果和照片參照，再決定是否安全重跑；D1 不可讀或結果不明就保持待查，不能重新上傳、刪除可能已引用的照片或宣稱已發布。備份還原則須完成刪除／撤權重播、D1 事件序列及銀行／照片對帳；無法證明完整時保留停賣與特權操作關閉，不以舊快照直接恢復營業。

改店名、聯絡方式或個資告知時，依[部署規格](08-repeatable-deployment.md)先啟用獨立於 D1 的暫停閘，協調靜態品牌與店主核准的 D1 告知版本，逐一核對所有可達網址及快取後再開放新個資蒐集與結帳。純外觀失敗時，從上一個相容 Git 版本取回**樣式、排版與適用素材**，再以目前店名、聯絡方式及現行 D1 告知重建前端；不得整份回退帶有舊身分的品牌設定。D1 商品／訂單／庫存、收退款及資料告知保持最新，不能回滾 D1 快照來回退外觀。若連店家身分也要回退，仍先啟用暫停閘並完成靜態與 D1 的成對更新核對。商品照發表與清理則按[本機發布](06-local-publishing.md)的操作 ID、D1 結果和照片參照核對，不因 agent 未收到回應就刪已引用照片。

### 兩種 agent 的驗收

- 從**乾淨公開範本**分別啟動 Codex 與 Claude Code，確認各自能以同名 skill 明確呼叫，也能從相關自然語句發現正確入口；一般不相關改碼任務不誤觸發。兩個短入口的觸發描述及共用文件目標一致，所有連結有效，`AGENTS.md` 未變動。
- 用相同繁體中文情境跑初次設定、只改品牌、新品牌圖片、依實拍做單件展示照、缺少來源照／缺少生圖工具、要求越界改結帳或退款等案例；兩種 agent 均只改允許檔案，缺圖明確交接，未把首店資料、私有照片或憑證帶入新店／Git／測試資料。
- 手機與桌面預覽及測試環境驗證公開商品實拍、AI 標示、價格與期限、LINE 登入、邀請核准與撤銷、競買結帳、舊訂單查詢、後台待辦與二次確認、逐筆退款、寄送售後、照片清理、個資告知及資料請求仍可用；測試帳號、LINE channel、D1／R2 與正式商店隔離。品牌改名、失敗回退、備份逾 48 小時的**全部關鍵寫入**停止，以及資料無法完整復原時維持停賣，都照既定狀態處理。[後台待辦](12-admin-workflow.md)
- 枚舉正式與測試的兩個 Worker、所有自訂／預設／Version／Preview 網址及 R2 直連網址，檢查 Access 與 Host 邊界、未知入口拒絕、店主舊 session 撤權、LINE 管理員權限撤銷；發布器新服務權杖只可進指定路由，舊權杖撤銷後不可進入，均不能藉改版開啟旁路。[部署驗收](08-repeatable-deployment.md)
- 兩種 agent 的輸出都含同格式的差異、素材來源、檢查結果與店主手動發布交接；任何檢查或人工比對未完成時標示未完成，不聲稱已上線。只有可改清單與真實指令隨應用一同實作並跑過上述兩種 agent 的乾淨複製驗收，才能宣稱範本支援該版客製化流程。
