# 定義顧客核准與管理員權限

Type: grilling
Label: wayfinder:grilling
Status: resolved
Blocked by: 03

## Question

顧客首次 LINE 登入後如何顯示待核准、由誰核准或撤銷購買資格、權限變動如何影響購物車與既有訂單？管理員如何取得及恢復後台權限？定義公開頁、顧客頁和後台頁的權限邊界。

## Comments

- 已確認：首次成功 LINE 登入會自動建立待核准顧客；商品維持公開，待核准者不能加入購物車或下單。
- 已確認：店主經 Cloudflare Access 驗證後，可新增 LINE 帳號作為後台管理員。角色分為店主與管理員；店主可指派或撤銷管理員，兩者均可核准顧客及處理訂單。Cloudflare Access 的實際邊界與額度正由官方文件查證。
- 已確認：待核准者以邀請碼核對，具體兌換與核准規則待決定；撤銷顧客資格時立即禁止新購買並清空購物車，但保留其既有訂單查看與付款回報；拒絕或撤銷狀態不因再次登入自動重排，須人工重新核准。
- Cloudflare Access 官方查證見[研究筆記](../research/cloudflare-access.md)；店主入口與 LINE 管理員入口需要各自驗證權限。
- 已確認：店主或管理員為受邀者建立每人一次性、7 天有效的邀請碼；首次 LINE 登入後兌換即可取得購買資格。LINE 管理員須先完成登入，店主確認本人後才授權；店主失去 Access 權限時透過 Cloudflare 管理介面恢復，LINE 管理員不自動接管。管理員身分與顧客購買資格互不隱含。
- 已確認：拒絕或撤銷資格後，不能再靠新邀請碼自行恢復，須由店主或管理員人工重新開通。管理員不能核准自己的購買資格或確認自己的付款；由店主或另一位管理員處理並留下紀錄。
- 已確認：受邀者先完成 LINE 登入成為待核准者，將申請編號交給店家；店主或管理員為該 LINE 身分產生專用邀請碼，只有該身分可兌換。

## Answer

### 身分與購買資格

- 商品目錄對匿名訪客公開。顧客首次成功 LINE 登入後，以經伺服器驗證、屬於本站 LINE channel／provider 的 user ID 建立「待核准」紀錄並顯示申請編號；LINE 顯示名稱只供辨識，不作身分鍵。[LINE 身分查證](../research/line-login.md)
- 店主或管理員針對該待核准 LINE 身分建立專屬邀請碼。邀請碼只可兌換一次，7 天後失效；須由綁定的 LINE 身分在登入後兌換，成功即取得購買資格。不可用它授予後台權限；LINE 管理員不能為自己的顧客身分核發邀請碼。核發、兌換及失效須可追查；實作時避免儲存可直接使用的明文碼，並防止猜碼或重複兌換。兌換與同時發生的拒絕／撤銷須有單一、不可分割的結果，詳見[邀請碼一致性票](15-invite-redemption.md)。
- 拒絕或撤銷購買資格後，再次登入或取得新邀請碼均不自動重新核准；店主或管理員須明確重新開通。撤銷立即禁止新增／操作購物車及結帳，並清空既有購物車；既有訂單不自動取消，顧客登入後仍可查看自己的訂單及回報付款，按既定生命週期由管理員處理。[訂單生命週期](01-order-lifecycle.md)

### 角色與授權

| 身分 | 可執行的動作 |
| --- | --- |
| 匿名訪客 | 瀏覽公開商品 |
| 待核准顧客 | 瀏覽、查看申請狀態、兌換只綁定自己的有效邀請碼 |
| 核准顧客 | 瀏覽、加入購物車、結帳、查看與回報自己訂單的付款 |
| 被拒絕或撤銷的顧客 | 瀏覽、查看與回報既有自己的訂單；不能再購買或用邀請碼自行恢復 |
| LINE 管理員 | 核發邀請碼、核准／撤銷顧客、處理訂單；不能指派管理員，且不能核准自己的購買資格或確認自己的付款 |
| Cloudflare Access 店主 | 管理員的全部商店操作，以及指派／撤銷 LINE 管理員 |

LINE 管理員須先登入，讓商店取得經驗證的 LINE user ID；店主確認本人後才授權。管理員資格與顧客購買資格互不隱含。店主使用 Cloudflare Access 保護的入口；LINE 管理員使用自己的 LINE 登入入口，兩者在伺服器端按動作檢查當前授權，不能由瀏覽器資料、顯示名稱或尚未驗證的標頭決定角色。購物車修改與結帳檢查當前購買資格；既有訂單查看與付款回報檢查登入者是否為該訂單顧客，不因購買資格撤銷而拒絕；後台操作檢查當前店主或管理員授權。撤銷管理員權限後，下次特權請求即遭拒。核發邀請碼、權限變更與管理員訂單動作記錄操作者、對象、時間及原因。管理員也不得核對或核准自己的退款。[Access 查證](../research/cloudflare-access.md)

店主失去 Access 入口時，透過該店 Cloudflare 管理介面修正 Access 規則；若更換遭盜用或失去控制的店主身分，也須撤銷舊 Access session，不能只改 Allow 規則。[Cloudflare session 管理](https://developers.cloudflare.com/cloudflare-one/access-controls/access-settings/session-management/) LINE 管理員不自動接管店主權限，也不設未驗證的網站緊急入口。各店 Access 政策、可達網址及 LINE channel 的具體設定由[獨立部署票](08-repeatable-deployment.md)定義；結帳時資格撤銷與保留庫存的競爭由[結帳一致性票](07-checkout-consistency.md)驗證。
