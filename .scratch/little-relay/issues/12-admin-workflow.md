# 定義後台待辦與管理動作

Type: grilling
Label: wayfinder:grilling
Status: resolved
Blocked by: 04, 06, 07, 10, 15

## Question

店主和 LINE 管理員每日要如何看見待核准顧客、已核發或已兌換的邀請碼、即將到期的待付款訂單、付款待核對、退款處理中、待寄送訂單、已售商品與待下架內容？店主如何新增／撤銷 LINE 管理員？每類待辦可執行哪些動作，包括核發綁定 LINE 身分的邀請碼、人工重新核准、延長或重設期限、核對款項、整單取消、退款確認及人工重新上架？哪些動作需要確認、自我操作限制、錯誤提示和可追查紀錄，何時由本地上架指令處理、何時由後台處理？列出首版必要頁面與操作情境，不預先決定視覺設計。

已確認後台須區分「暫停販售／恢復」與「永久撤下」；退款後重新販售前須先完成本機照片發布，並提供照片清理失敗的待辦。

已確認要顯示逾期款項回報，供管理員人工核對；其處理不得自動恢復已釋出的訂單或商品保留。

依[邀請碼一致性規格](15-invite-redemption.md)，後台須顯示每位待核准顧客目前是否已有有效碼及到期時間，支援任一現任管理員作廢／補發並記錄原因；明文只在核發成功時顯示一次，回應遺失後只能查結果、作廢補發。顧客重送已兌換碼時，原結果尚在保留期限內才查原結果與目前資格；屆滿後只顯示目前資格與通用舊碼失效訊息。拒絕／撤銷不能被舊碼重新開通。

人工付款／寄送規格另要求顯示不足款補款追蹤、超額或重複入帳退款、退款失敗、門市失效、待寄件與追蹤資訊、未取退件、遺失／損壞、七日退貨和其他售後案件、需人工聯絡及私有照片暫緩清理待辦；管理員不得確認自己的付款或退款。[人工付款與寄送規則](10-manual-payment-shipping.md)

## Comments

- 店家確認：後台首頁是共用待辦，先看退款失敗／結果不明與銀行疑點，再看 12 小時內到期及待核付款、待寄送、配送／售後異常、顧客核准，最後照片清理與一般商品待辦。不分派給個人，依實際操作記錄處理者。
- 店家確認：開頁、切換清單與完成動作時重新讀取，另提供手動刷新；第一版不持續輪詢。以訂單編號、申請編號及商品 ID 搜尋，按狀態篩選；逐筆操作，不做批次金流或資格變更。
- 店家確認：收退款、取消、拒絕／撤銷資格、核發／作廢邀請碼、寄出／交付、永久撤下與重新上架、授予／撤銷管理員，以及發布全店收款／運費等店規版本，都顯示影響摘要並二次確認。一般查閱與備註不加確認。
- 店家確認：全店收款帳戶、運費、服務範圍及付款／退貨政策只由 Access 店主發布新版本；LINE 管理員可按現行設定處理個別訂單。人工聯絡記下實際時間、方式和結果後，聯絡待辦才算處理，未結案件繼續顯示。
- 一致性補充：人工退款須先在 D1 原子保留額度再向銀行匯款，防止兩名管理員在資料庫記帳前雙重匯款；個資請求按既定資料生命週期列店主待辦。這些是已定金額上限與資料請求規則的操作前置條件。

## Answer

### 首版頁面與共用待辦

| 頁面 | 必須看見的證據與可執行動作 |
| --- | --- |
| 首頁待辦 | 由 D1 當前紀錄推導各類待辦數量與摘要，連到明細；不是另有一份可手動勾掉的任務狀態。先列退款失敗／結果不明、未歸屬或重複銀行入帳、逾期款項；再列 12 小時內到期、付款待核對與補款追蹤，以及個資請求將逾期／已逾期；接著待寄送、配送／售後及聯絡、待核准顧客；最後公開照清理失敗與一般商品待辦。異常即使跨類別也要保持可見 |
| 顧客與邀請 | 申請編號、經驗證 LINE 身分提示、目前資格、有效碼到期／核發／兌換結果與歷史。核發、作廢、補發單一綁定碼；拒絕、撤銷或人工重新開通。明文碼只在核發成功時顯示一次，補發前查原結果；不能核准自己或靠舊碼重開資格。[邀請碼一致性](15-invite-redemption.md) |
| 訂單與對帳 | 訂單編號、顧客、商品及金額快照、當前保留／截止時間、付款回報、可核對的銀行入帳識別與歸屬、已退及進行中／結果不明退款保留額、可退餘額及操作歷史。到期前延長；期限內記錄待核入帳並暫停到期；逐筆認領、處理少付／多付、確認收款、查無款項時給**新期限**或在核清後整單取消；退款先取得專屬額度再人工匯款、核對結果；逾期款項另處理，不能復活舊單。[結帳一致性](07-checkout-consistency.md)、[人工對帳](10-manual-payment-shipping.md) |
| 寄送與售後 | 已收款待寄件、交付方式及必要收件資料、人工通知紀錄、門市失效、追蹤資訊、實際收受日、未取退件、遺失／損壞、退貨／售後訊息、退款與照片保留待辦。管理員記錄寄出或面交、收受日、聯絡結果、退件與售後進度；按既定規則人工退款或重寄。售後不抹除原已完成事件。[寄送與售後](10-manual-payment-shipping.md) |
| 商品與照片 | 商品 ID、目前公開／暫停／保留／售出／撤下狀態、公開照片清理失敗及本機發布結果。後台可暫停／恢復、永久撤下、核對退款後重新上架及重試照片清理；商品標題、價格、衣況和照片仍由本機預覽發布，不在後台直接修改。已售重上架須先在本機補現況照並核對，不是直接切換狀態。[本地上架](06-local-publishing.md) |
| 店主專用設定 | 已完成 LINE 登入的候選管理員身分、目前管理權與撤權紀錄；授予／撤銷管理員。另查看並發布收款帳戶、運費、服務範圍、付款／退貨規則及個資告知的新版本，顯示影響新單與舊單的界線；LINE 管理員不可進行全店設定發布。[角色權限](04-buyer-approval.md)、[人工付款與寄送](10-manual-payment-shipping.md) |
| 店主個資請求 | 顧客在帳號／訂單頁提出或失去登入後人工核對的查閱、更正、停止利用、刪除申請；顯示申請時間、身分核對、類別、適用決定期限、未結款項／售後的必要保留理由及目前狀態。店主記錄准駁、原因、通知與實際完成時間；若需依法延長，記錄通知及新期限。未完成或逾期仍列待辦。[資料生命週期](09-customer-data.md) |

共用待辦只作導覽，不取代訂單、帳目、資格、商品或售後的真實狀態。列表支援按訂單編號、申請編號或商品 ID 搜尋及狀態篩選；LINE 顯示名稱僅供提示，不以完整手機號碼作一般搜尋。清單按需分頁讀取；開頁、切換清單、提交動作後及手動刷新時更新，不持續輪詢。12 小時只是**提示門檻**，付款截止與商品釋出仍由 D1 即時交易判定；舊畫面不能讓已到期訂單被延長或確認錯誤款項。

### 操作確認、權限與失敗回復

- 高影響動作先呈現目前狀態、涉及的顧客／商品、金額、期限或資格變化，並要求管理員明確二次確認：核發／作廢／補發邀請碼、拒絕／撤銷／重開資格、確認收款、整單取消、**建立／認領退款意圖及確認退款結果**、標記寄出／交付、永久撤下與重上架、授予／撤銷管理員及發布全店店規。退款確認摘要還須顯示收款人、遮罩帳戶、金額及剩餘可退額。暫停販售、一般備註、查閱和刷新不需額外確認。每次動作記錄操作者、對象、時間、原因與結果；人工聯絡另記實際時間、方式及結果，聯絡步驟完成後才清除該提醒，仍有待買家回覆或退款時相關案件不消失。
- 伺服器每次提交重新核對店主 Access 或 LINE 管理員**當前**權限、不得處理自己的顧客資格／付款／退款、目標當前狀態與版本；不能以畫面剛才顯示的可操作狀態當作許可。LINE 管理員的 D1 角色資格須與付款確認、退款意圖／結果、取消、庫存或資格等特權寫入在**同一筆 D1 交易**核對；撤權先提交則舊頁面、session 及重送請求不能再改資料，動作先提交則保留其結果。店主 Access 是外部權限，須在伺服器端驗證，其撤權與 D1 的邊界交由[獨立部署票](08-repeatable-deployment.md)驗證。二人同時操作時，只有符合前置條件並先成功提交的一方生效；另一方顯示最新狀態與下一步，不能顯示假成功。[顧客權限](04-buyer-approval.md)
- 每筆財務與資格動作帶操作識別，逾時或回應遺失時先查 D1 原結果，再決定是否安全重試。**人工銀行退款**先在 D1 取得不可重複的退款額度保留，再由一位管理員原子認領執行，才向銀行匯款；僅執行人可查看完整帳戶，其他人只見操作識別、已保留金額及遮罩帳戶。匯款後核對銀行實際結果與交易參考，不能因 D1 未記到成功就再次匯款；只有已證實成功才可確認退款，只有銀行證實未匯出才可釋放保留。執行人中斷時保持意圖鎖定，店主查銀行後才能交接；結果不明不能交給另一人重匯。銀行帳目唯一歸屬、已確認入帳與包含進行中退款的額度上限、資格／邀請碼狀態及整單庫存釋放由 D1 原子條件強制；退款失敗或結果不明時保留待辦和商品不可購買，不可按「已處理」移除。若 D1／R2 失敗或額度耗盡，顯示暫不可處理，保留原狀與未結待辦，待恢復後核對結果再操作。[付款規則](10-manual-payment-shipping.md)、[照片與發布](06-local-publishing.md)
- 後台顯示的收款帳戶、交付政策和個資告知取自各自現行 D1 版本；發布新版本須由店主確認，不改已成立訂單快照。若舊單需改付款指示，須在該單記錄新舊版本、人工聯絡與結果，不因改全店設定默改舊單。[資料邊界](05-data-image-boundary.md)、[資料生命週期](09-customer-data.md)

### 驗收情境

- 同一邀請碼補發／兌換、同一顧客核准／撤銷、管理員撤權對上付款確認／退款意圖與結果／取消等特權動作，都只有一個權威結果；自我操作被拒，舊碼與舊 session 不重新授權。
- 期限前延長或記錄部分入帳與排程逾期競爭時，清單可能尚未刷新，但提交必依 D1 當前時間與狀態；逾期回報不恢復原保留。兩名管理員認領同一入帳、重複按確認收款或退款、兩筆退款意圖同時接近餘額上限時，只有額度內的意圖可在**銀行匯款前**成立；同一退款意圖同時被兩人開啟或認領時只有一人可執行，執行人中斷後不得未經銀行核對交接；銀行結果不明時不得釋出額度或重匯，實際與 D1 都不能超退。
- 取消整單與他人結帳、暫停／恢復與本機發布、退款後重上架與照片準備交錯時，畫面須指出衝突與目前商品狀態；不能誤釋保留、直接復活已售商品或刪掉訂單私有照。
- 退款結果不明、門市失效、退件、配送遺失、七日邊界及仍在處理的售後案件仍列待辦；人工聯絡有時間與結果，不因單次聯絡就結束未完的退款／售後；售後未結時私有照片清理暫緩。
- 開頁與動作後更新、手動刷新、搜尋及分頁能找到對應紀錄；12 小時提示與真正截止獨立，長時間未刷新後點舊按鈕只得到最新結果；暫停輪詢時清單讀取不隨開頁時間持續增加。
- 個資查閱與更正／刪除請求從提出、核對、准駁、必要延長通知到完成皆可追查；即將到期和已逾期仍列店主待辦，未結案件的暫留原因及結案後刪除期限正確。[資料請求規則](09-customer-data.md)
