# 定義每店品牌、頁面與生成圖片的修改邊界

Type: grilling
Label: wayfinder:grilling
Status: resolved
Blocked by: 06, 07

## Question

下載範本的家庭需要提供哪些品牌資料，並可修改哪些文字、配色、字體、版面、頁面區塊與品牌圖片？比較每店設定與素材包、限定範圍的原始碼修改、執行時管理介面等方式，決定哪些區域可由 AI agent 改動，哪些 LINE 授權、訂單及庫存規則必須維持一致。商品實拍照與可生成的品牌圖片如何區分？範本內附圖片、字體與範例素材是否有再散布權利？生成圖片的輸入權利、服務條款、來源與替換紀錄要如何保存？

## Comments

- 店家確認：每店先填店名、簡介、品牌語氣、主色、標誌與公開聯絡方式；字體及次要配色可先沿用範本。本機品牌設定檔加素材包是一般修改入口，不建執行時品牌編輯後台。
- 店家確認：AI agent 可在指定前端區域修改各頁視覺與排版，須留下可檢查的差異；伺服器的 LINE 身分、顧客核准、結帳、庫存、訂單與付款規則不屬於品牌修改。頁面不得隱藏價格、商品照片標示、付款期限、狀態、必要欄位或操作入口。
- 店家確認：範本只附自製或權利允許再散布的字體、圖片與範例內容，否則用中性占位；不夾帶首店商品照、顧客資料或憑證。生成品牌圖保留來源、工具、提示與人工確認紀錄，預設不用可辨識家庭照片。
- 店家確認：交易政策與品牌包分開；發布前預覽手機及桌面畫面、人工確認素材與文案，並驗證登入、核准、結帳、訂單及後台流程。品牌改版失敗只回退前端與素材版本，不回滾 D1 資料。

## Answer

### 每店品牌包與編輯邊界

- 複製者在本機維護**一份每店品牌設定**及對應的版本化靜態素材包。必填店名、簡介、品牌語氣、主色、標誌（可用純文字標誌）及對外聯絡方式；字體、次要配色、導覽名稱、首頁文案與裝飾圖可沿用安全預設再調整。一般換品牌由建置產生靜態頁與資產，品牌瀏覽不增加每次請求的 D1 讀寫。[靜態資產邊界](05-data-image-boundary.md)
- 品牌設定只擁有視覺與介紹文字。商品名稱、價格、照片、庫存與訂單由既定發布及 D1 流程處理；收款帳戶、交付方式／範圍、運費及付款／退貨說明屬**版本化營運設定**，由 D1 的現行版本與訂單快照管理。頁面可讀取並顯示該版本，但品牌文案不可另存一份會與交易政策分歧的值。[人工付款與寄送規則](10-manual-payment-shipping.md)、[結帳一致性](07-checkout-consistency.md)
- 個資蒐集目的、類別、利用方式／期間及權利申請方式由每店 D1 中**單一、另行版本化的個資告知設定**提供，含店家身分、資料請求聯絡方式與生效日期；它不是可隨品牌語氣自由重寫的介紹文案。店主審核後才更新現行版本，登入、下單、退款前及帳號／訂單頁皆引用它，不在各頁複製不同內容。品牌包中的公開店名／一般聯絡方式若變更，須先在伺服器端暫停新登入、結帳及其他新個資蒐集，再更新靜態品牌與 D1 告知；所有可達網址驗證兩者一致後才恢復，不讓部署先後造成不一致期間仍收資料。D1 暫不可讀時也停止新個資蒐集；實際發布與舊版留存由[獨立部署票](08-repeatable-deployment.md)落實。[顧客資料生命週期](09-customer-data.md)
- 若設定與素材無法表達所需設計，AI agent 可修改明確列為介面所有權範圍的前端元件、樣式與公開內容區塊，涵蓋首頁、商品目錄／詳情、顧客頁與後台頁的**呈現**。實作時須列出實際可編輯路徑和不可編輯路徑，保留差異供店主審閱；此票不預設尚不存在的檔名。身份驗證、邀請、授權、商品發布與庫存、結帳交易、訂單狀態、付款對帳和伺服器 API 均在該範圍之外。即使介面改壞或被繞過，伺服器仍按原規則檢查權限、版本與交易。
- 視覺重排不可移除或淡化商品價格／可售狀態、實拍與「AI 展示照」標示、瑕疵資訊、訂單應付金額與期限、交付及付款條款、個資告知與資料請求入口、顧客確認步驟、後台待辦與錯誤回饋。可增減或重排**非交易性的介紹區塊**，但所有必需頁面與動作仍可找到、可用於手機並符合基本對比、鍵盤操作與替代文字要求。單改 CSS 不等於通過功能驗收。

### 素材與圖片來源

- 品牌標誌、首頁主圖、裝飾圖與字體隨網站靜態資產部署；它們與每件商品的**實物實拍／AI 展示照**分開。商品照仍由本機逐件預覽確認後發布至 R2，訂單保存自己的照片快照，不能把商品照放入品牌素材包或隨範本再散布。[本地上架工作流](06-local-publishing.md)
- 範本只含製作者自有、明確允許範本再散布，且記錄來源／授權條件的素材；來源不明時用文字標誌、已有權利的字體或中性占位，不先使用再補證明。每店新增圖片與字體也先核對來源及使用條款；此票不替未選定的生成服務、字體或圖庫宣稱授權。範本下載包不得含首店的商品原圖、生成商品照、顧客或訂單資料、付款資料與憑證。[顧客資料生命週期](09-customer-data.md)
- 每張生成品牌圖在品牌包旁保留**素材紀錄**：用途、來源素材及輸入權利、生成服務與模型／版本、日期、提示詞或可重做的設計說明、輸出檔版本／雜湊、當時的使用條款或授權依據、人工審核者與結果。紀錄不得包含密鑰、顧客資料或未清理的家庭照片。品牌圖可作風格表現，不能冒充某件商品實拍；商品展示照須遵守忠實衣況及頁面標示規則。
- 預設以文字風格說明及不識別個人的素材生成品牌圖。若店家要使用自己孩子或住家照片作輸入，先確認相關權利與同意，產生移除定位、住家細節及可辨識內容的工作副本，再確認所選工具的資料處理條款；原始照片留本機，不放進範本或素材紀錄。未通過檢查就不使用該輸入。商品圖使用可能連線的生成工具時，仍依[既定照片工作流](06-local-publishing.md)處理。

### 預覽、發布與回退

1. AI agent 先列出品牌設定、素材與介面檔案的差異，產生本機預覽；店主在手機和桌面檢查文案、聯絡方式、圖片、授權紀錄、商品實拍入口、價格、付款與交付說明、現行個資告知及資料請求入口，以及必要操作，批准後才發布。若改店名或聯絡方式，須先確認現行個資告知指向同一店家與可用聯絡管道。無標誌或未授權圖片時以安全預設呈現，不能留下壞連結或空白關鍵內容。
2. 品牌改動仍跑既有登入、邀請核准與撤銷、商品內容／照片標示、購物車、整單結帳、訂單快照、付款回報及後台操作驗收；同時檢查手機呈現、對比、鍵盤與圖片替代文字。具體命令、可編輯路徑與 agent 引導步驟由[AI agent 客製化指引票](14-agent-customization-workflow.md)在技術選型後落實。
3. 保留前一版品牌設定、素材及前端建置版本。新外觀有錯時只重新部署前一版靜態介面及品牌資產；以版本化資產網址或快取更新使替換生效。純外觀回退須以**目前**店名／聯絡方式重新建置舊版樣式；若要連店家身分一起回退，先暫停新個資蒐集與結帳，依上段流程更新靜態品牌及店主核准的 D1 告知並驗證一致後再恢復。**不可回復舊 D1 快照**來撤銷品牌改版，因為那會倒退現有商品、訂單、顧客資格或付款紀錄。[獨立部署票](08-repeatable-deployment.md)

驗收至少包含：新店下載包沒有首店資料或商品照；改店名、主色、首頁區塊與生成主圖後可預覽與發布，改名與回退時公開店家身分／聯絡方式和現行個資告知一致，任一更新只完成一半時仍停止新個資蒐集與結帳；商品實拍仍可見且 AI 圖標示清楚；登入、下單、退款與帳號頁都顯示同一現行個資告知並可提出資料請求；兩人競買、停權者結帳、舊單查詢與後台動作不因 UI 修改而放寬；移除必要價格／期限／個資告知或更動伺服器交易規則的差異被驗證擋下；缺圖或權利不明時使用安全預設；外觀回退後 D1 訂單與庫存保持最新，且不把告知內容退回失效版本。
