# 定義獨立商店的複製部署與營運邊界

Type: grilling
Label: wayfinder:grilling
Status: resolved
Blocked by: 04, 05, 06, 07, 09, 10, 13

## Question

一個新家庭如何從可下載範本建立自己的品牌設定與素材、網域、Cloudflare 資源、LINE channel、Cloudflare Access 店主入口與政策、LINE 管理員、秘密設定與商品資料？如何檢查自訂網域、預覽及平台預設網址均沒有繞過店主保護？店主失去 Access 入口或 LINE provider 改變時如何恢復或遷移身分；更換遭盜用的店主身分時如何撤銷舊 Access session？下載包如何確保不含首店的顧客資料、訂單、憑證和商品照片？哪些步驟可自動化，哪些需人工完成？定義免費額度監控、備份、遷移、程式與品牌素材回滾、資料修復的最低操作要求，避免為換品牌回滾既有訂單或庫存。

複製店設定還須包括自己的收款帳戶、服務區域、支援超商品牌、運費、人工聯絡方式及對顧客可保存的付款／交付／退貨說明；公開販售前核對該店是否為營業賣家及當地適用規則，不能直接套用首店的個人戶假設。首店若從偶爾出售自家二手衣轉為持續營業，也須重新檢查分類與顧客權利。[人工付款與寄送規則](10-manual-payment-shipping.md)

備份與還原的操作方案須落實[顧客與配送資料生命週期](09-customer-data.md)：加密備份最長 30 天、到期刪除；獨立保留可涵蓋備份視窗的最少刪除／撤權重播紀錄；隔離還原並重播清理、停權、LINE 轉綁、已兌換邀請與失效送單。還須選定備份後訂單、保留、售出、**進行中／結果不明的退款額度保留與唯一執行人認領**、已成功退款等已提交變動的權威重建來源並逐筆對照銀行；無法證明完整時不得重新開放結帳或特權操作，也不得重匯、交接或釋出不明退款額度。部署檢查也須驗證登入與下單前的店家資料告知、個資請求入口，以及新店不帶出首店的顧客、收件或退款資料。

依[品牌修改邊界](13-brand-customization-boundary.md)，複製部署須定義每店品牌設定與素材包的實際位置、靜態資產版本／快取更新、素材權利紀錄與授權檢查，以及只回退前端與素材而不倒退 D1 訂單／庫存的操作步驟；首店商品照與個資不得隨下載包散布。

每店 D1 另有單一版本化個資告知設定及權利申請聯絡方式；部署時必須填妥、由店主核對，讓登入、下單、退款及帳號頁引用同一現行版本。品牌改名、換聯絡方式或連店家身分一起回退時，須在第一個靜態／D1 變更前啟用所有入口共同遵守的伺服器端暫停閘，禁止新登入、結帳及其他新個資蒐集；兩邊發布完、各可達網址及快取版本核對一致後才關閉。純外觀回退維持目前店家身分，不能靠回復舊 D1 快照。舊版告知保留、版本對照及 D1 暫不可讀時停止收集新個資，須納入部署／還原操作。

依[邀請碼一致性規格](15-invite-redemption.md)，備份還原須證明補發／作廢、已兌換及拒絕／撤銷的權威狀態沒有倒退；若備份後的結果無法重建，先停用所有舊邀請碼的兌換並保持結帳關閉，直到人工核對資格與庫存後才恢復。

若 Access 店主同時有 LINE 顧客身分，部署／授權流程須建立可驗證的身分關聯，讓後台禁止店主對自己的顧客身分核發邀請碼或處理自己付款；Cloudflare Access 的外部撤權與 D1 交易不能假設原子同步，須驗證撤權後舊 session 與進行中的特權操作如何停止。

依[後台待辦規格](12-admin-workflow.md)，全店收款帳戶、運費、服務範圍、付款／退貨規則及個資告知的新版本只由 Access 店主發布；LINE 管理員只處理個別顧客、商品及訂單。後台清單按需載入並分頁，不持續輪詢；部署驗收須比較按需讀取與待辦可見性，避免為省額度漏掉退款或付款異常。

## Comments

- 店家確認：每店使用自己的 Cloudflare 帳號、自有正式網域與 LINE channel；店主在本機預覽、檢查後以 Wrangler 手動發布。正式公開商店及店主後台分成兩個 Worker，後者由整個 Worker 的 Access 政策保護。
- 店家確認：另設受保護的測試網域、測試 LINE channel 與獨立測試 D1／R2；不以正式資料測試。正式 Worker 關閉 `workers.dev` 與版本預覽網址。
- 店家確認：店主電腦每日排程把 D1 及仍須保存的 R2 照片加密備份到正式 Cloudflare 帳號外，最多保留 30 天。超過 48 小時沒有成功的帳號外備份，暫停所有會改變庫存、訂單、收退款及權限的網站寫入，直到備份及核對恢復。
- 店家接受保守復原邊界：優先使用仍在期限內的 D1 時間還原；若舊備份之後的交易、權限或刪除無法證明完整，繼續停賣並人工對帳，不把快照直接當成現況。

## Answer

### 每店資源與可複製邊界

每個商店使用自己的 Cloudflare 帳號、網域、LINE Login provider／channel、正式 D1、公開與私有 R2、Access 應用與秘密設定。公開商店 Worker 提供靜態頁、商品與 LINE 顧客／管理員 API；獨立的店主 Worker 只提供店主頁與店主專屬 API，使用另一個主機名稱。兩者只綁定該店資源，不包含跨店資料庫或共用額度。測試環境另有受 Access 保護的測試主機名稱、兩個測試 Worker、D1／R2 與 LINE 測試 channel；用合成資料驗證，不接正式庫存、顧客或銀行帳戶。每店自己的 Cloudflare 帳號才使帳號層級的額度與權限真正分開；資源只改名但留在同一帳號並不等於額度隔離。[Cloudflare Workers 限額](https://developers.cloudflare.com/workers/platform/limits/)、[D1 限額](https://developers.cloudflare.com/d1/platform/limits/)

下載包只含範本程式、空白或具再散布權利的品牌素材、設定範例、資料庫遷移與操作指引；**不得**包含首店商品照、顧客／訂單／收退款資料、實際品牌私有素材、環境檔、金鑰、Access 身分或 LINE secrets。每店的品牌設定與素材包在本機版本化，附素材來源與授權紀錄；商品主實拍和本機草稿留在 Git 排除的店家資料夾。交易設定及單一現行個資告知版本由該店 D1 管理，品牌包不能更改收款或交易規則。[品牌邊界](13-brand-customization-boundary.md)、[資料邊界](05-data-image-boundary.md)

### 首次部署、權限及更新

1. 店主準備自己的 Cloudflare 帳號及恢復方式、網域、LINE channel 與回呼網址；建立正式／測試 D1、R2、Worker 與 Access。公開販售前填妥收款帳戶、TWD／服務區域、支援超商、每單運費、人工聯絡方式、付款／交付／退貨說明與資料告知，並確認自己的營業身分及適用規則；不可照抄首店個人戶假設。[付款寄送規則](10-manual-payment-shipping.md)
2. 將每店資源 ID、網域與非秘密設定寫在店家設定；LINE、Cloudflare、R2 及加密金鑰用受限 secret／本機安全儲存提供，不進 Git、品牌包或客戶端。先執行 D1 遷移，再由已驗證的 Access 身分建立首位店主；以經驗證的 LINE 身分建立店主與其顧客身分關聯，以供自我操作禁止。LINE 管理員須先登入，再由店主核對後授權；不能從範本預設資料直接取得管理權。本機發布器另使用**獨立機器身分**：Access 服務權杖只准進入指定發布路由，伺服器依驗證後的 service client ID、商店、權杖版本與 D1 當前發布權限核對；它不得進入店主頁、店規、顧客、訂單或退款路由，也不冒充有 `sub` 的真人店主。R2 長期 bucket 權杖只留在伺服器；發布器經授權後取得限時、限該次操作鍵前綴的暫時憑證，不能藉此讀取其他訂單私有照片，並須定期輪替上層權杖。發布介面仍須遵守商品版本、庫存及暫停閘。[Workers secrets](https://developers.cloudflare.com/workers/configuration/secrets/)、[Access 服務權杖](https://developers.cloudflare.com/cloudflare-one/access-controls/service-credentials/service-tokens/)、[R2 暫時憑證](https://developers.cloudflare.com/api/resources/r2/subresources/temporary_credentials/)、[權限模型](04-buyer-approval.md)、[本機發布](06-local-publishing.md)
3. Access 應套在**整個店主 Worker**，涵蓋自訂網域與其他可達入口；檢查是否有較具體的網域政策覆蓋此保護。店主 API 仍須驗證 Access JWT 的簽章、簽發者、受眾與期限；每次特權寫入須在**同一筆 D1 交易**核對當前店主身分與授權版本後提交變更，發布機器及 LINE 管理員也在自己的 D1 寫入交易內核對當前授權。若撤權先提交，先前已進入 API 的請求也不能提交；若原動作先提交，保留其既成結果並記錄先後。公開 Worker 不放店主專屬路由；兩個 Worker 對未知 Host 拒絕，API 路由不得被靜態資產路由繞過。正式設定明確關閉 `workers_dev` 和 `preview_urls`；Cloudflare Previews 是另一功能，首版不開啟，逐一檢查網域、路由與控制台可達網址。店主 Access 失效時只經該店 Cloudflare 管理介面恢復；遭盜用時先啟用獨立於 D1 的暫停閘並提交 D1 店主撤權，再撤銷 Access 使用者及既有 session，逐一驗證舊 session 及撤權後寫入被拒。Access 外部撤權與 D1 交易不能假設原子同步。[Worker Access](https://developers.cloudflare.com/workers/configuration/cloudflare-access/)、[JWT 驗證](https://developers.cloudflare.com/cloudflare-one/access-controls/applications/http-apps/authorization-cookie/validating-json/)、[Version URLs](https://developers.cloudflare.com/workers/versions-and-deployments/version-urls/)
4. 在獨立測試環境完成匿名瀏覽、LINE 登入與邀請碼、結帳競買、店主與 LINE 管理員權限、自我操作禁止、付款與退款待辦、個資請求、D1／R2 故障及額度耗盡的檢查。確認手機／桌面品牌內容、素材權利、付款指示、資料告知與每個可達網址一致後，店主本機執行建置和檢查，手動發布正式版並做同一組安全的正式冒煙檢查。每次發布記錄程式／靜態資產版本、D1 遷移、品牌與店規版本及操作人；以內容雜湊的資產網址更新快取。首版無 GitHub Actions 發布憑證。[品牌發布](13-brand-customization-boundary.md)

店主換網域或 LINE provider 時，先暫停新增個資與交易，更新全部回呼、Access 及 Host 白名單並逐一驗證；LINE 穩定 ID 不跨 provider 自動合併，舊訂單只在人工核對後轉綁。[身分生命週期](09-customer-data.md) 若改店名、身分或資料告知，先開所有入口共同遵守、位於 D1 之外的暫停閘，再協調靜態頁與 D1 版本；兩邊及快取均驗證一致後才開放。純視覺回退保留目前店家身分及 D1 店規版本，只回退品牌包／前端；Worker 版本回滾不回復 D1 或 R2，舊程式若不相容目前遷移或 binding，就以相容版本修復，不倒退訂單與庫存。[Workers rollback](https://developers.cloudflare.com/workers/versions-and-deployments/rollbacks/)

### 備份、額度及故障復原

店主電腦每日排程匯出 D1，連同當時應保存的公開商品照、私有訂單照片、物件清單、資料庫 schema／發布版本加密後，存於正式 Cloudflare 帳號外；密鑰另存，記錄成功時間、失敗告警與可還原驗證。D1 匯出可能暫時阻擋請求，安排在低流量時段。[D1 匯出限制](https://developers.cloudflare.com/d1/best-practices/import-export-data/) 備份最多留 30 天，逾期及已刪個資須按[資料生命週期](09-customer-data.md)清除；R2 到期規則可能延遲執行，期限敏感資料要主動刪除並驗證。[R2 lifecycle](https://developers.cloudflare.com/r2/buckets/object-lifecycles/)

在獨立的私有 R2 區保存最少的刪除、撤權、LINE 舊身分失效、邀請碼失效／消耗與送單失效重播紀錄，涵蓋任何仍可還原的備份。會降低權限或刪除資料的動作先持久記錄，再提交 D1；紀錄失敗時動作不顯示成功，啟用暫停閘並由店主處理。日備份連同該紀錄加密複製到帳號外；最後一份早於某筆紀錄的可還原備份到期、且無未結復原案件後，才清掉該筆最少重播資料。R2 與 D1 沒有共同交易，所以 D1 成功與 R2 寫入成功不能互相推定；中斷造成的保守拒絕由店主核對修復。[R2 儲存與計費](https://developers.cloudflare.com/r2/platform/pricing/)

備份後的**正向交易**以 D1 為正常營運時的唯一權威來源：送單、保留／售出、退款意圖額度、唯一執行人認領及結果，都在原本的 D1 業務交易內一併寫入不可任意改寫、具操作 ID 與連續序號的事件紀錄。復原前封住寫入並匯出當前 D1；只有當該匯出的事件序列從所選備份／Time Travel 書籤的序號到封存時的最高序號完整、與訂單／商品／退款狀態及銀行逐筆吻合，且相應私有照片快照可核對，才可把事件重播至隔離資料庫。若目前 D1 或事件序列本身損毀、最高序號無法可信驗證，或帳號遺失致使匯出不可取得，**沒有保證完整的正向重建來源**，維持停賣而不從銀行帳目猜測缺漏訂單。事件紀錄不存完整退款帳戶或多餘個資；只在仍有較早、可還原的備份需要重播時保留可連回訂單的內容，最遲隨相應的訂單／操作到期清理，未結案件按既定期限暫緩。清理前建立只含最後連續序號的檢查點，且僅在所有可還原備份的序號都已到達檢查點時刪除舊事件內容；後續事件由該序號繼續，還原仍須驗證連續性。訂單／操作的一年稽核紀錄另按[資料生命週期](09-customer-data.md)保存與去識別化，不靠永久保留重播內容。事件紀錄不是第二個線上交易真實來源。[結帳一致性](07-checkout-consistency.md)、[退款認領](12-admin-workflow.md)

備份逾 48 小時未成功，所有會改變庫存、訂單、收退款與資格的網站寫入停用；仍可瀏覽商品、查既有訂單及取得人工聯絡方式。加密副本已在帳號外落地並通過清單／解密驗證後，備份器才記錄成功時間；每筆業務 D1 交易依資料庫時鐘核對這個時間及暫停版本，查不到或過期就拒絕。本機發布器在上傳 R2 前預檢備份狀態，發布 API 仍獨立阻擋 D1 變更；直接上傳但未引用的照片列待清理，不算成功上架。到期釋出庫存、收款／退款、照片換版與其他排程業務寫入同樣遵守暫停；必要的個資清除走店主留證的受控例外，先記重播紀錄，不能靠一般交易入口繞過。緊急收退款或個資請求由店主在站外留證據，復原後逐筆核對補登。正式 Worker 的所有交易入口均即時遵守暫停閘，不能只靠後台畫面警告。平時靜態頁與快取承擔公開流量；D1 清單按需分頁、無持續輪詢，R2 圖片限尺寸並用自有網域快取。每週檢查 Workers、D1、R2 用量與帳單，於約 50%／80% 預算發出警示並停止非必要上架；不把警示當硬性費用上限。D1、R2 或免費額度不可用時停止結帳及相應後台動作，保留可用的靜態說明與人工聯絡入口。[免費額度查證](02-cloudflare-github-facts.md)

復原先在 D1 **之外**啟用涵蓋所有可達入口的暫停路由，並以 D1 寫入版本在同筆交易擋住先前已入站的請求；確認路由生效、既有寫入完成或被拒後，封存目前 D1 匯出，才開始原地還原。暫停期間封住新登入／個資收集、邀請兌換、結帳、庫存與財務特權寫入；暫停狀態不能隨舊 D1 快照倒退。七天內可用 D1 Time Travel 時先評估它；Free 的時間還原窗為七天，且是覆寫原庫的原地操作，非建立副本。[D1 Time Travel](https://developers.cloudflare.com/d1/reference/time-travel/) 其他情形在隔離 D1 演練匯入與照片清單。只有前述 D1 事件序列及私有照片完整可驗證時，才重播備份後的正向變動；另重播刪除／撤權紀錄，逐筆核對訂單、保留、售出、退款額度保留、執行人認領、銀行實際入退款及售後狀態。帳號整體遺失時，同帳號 R2 的新重播紀錄也可能遺失；未能用外部證據證明授權、刪除及所有交易完整時，**不得**重新開放結帳、邀請兌換或特權財務操作，也不得重匯或釋出結果不明的退款額度。必要時重新核對身分、重建資格；單靠銀行帳目無法證明沒有未回報的訂單。這是刻意接受的停賣風險，不宣稱每日快照提供零資料遺失復原。[資料生命週期](09-customer-data.md)、[後台財務邊界](12-admin-workflow.md)

### 驗收條件

- 淨化後的下載包與新店測試環境找不到首店照片、顧客／訂單／退款資料或任何可用憑證；測試網域、LINE channel、D1／R2 與正式環境互不串接；舊店品牌素材也不從快取洩漏。
- 枚舉正式、測試、`workers.dev`、Version URL、Cloudflare Preview 與 R2 直連網址，檢查 Access 網域政策沒有覆蓋整個店主 Worker 的保護；未授權者不能碰店主 API，未知 Host、過期 Access JWT、撤銷後舊 session 與 LINE 管理員舊權限均不能寫入。用服務權杖只能發布合格商品內容，不能讀取店主頁、變更店規／權限或操作訂單；服務權杖撤銷後重送失敗。店主自己的 LINE 顧客資格／付款／退款由其他有權者處理。
- 產品版本或品牌回退只改介面及素材；新舊店規、告知與舊訂單快照仍可正確查閱，身分／告知同時變更期間沒有新個資收集或結帳。
- 演練 48 小時備份逾期、D1 故障、R2 照片故障、額度耗盡、七天內 Time Travel、較舊備份及整帳號遺失：本機發布與排程業務寫入也被擋；撤權先於在途寫入提交時，舊請求失敗。還原需檢查正向事件連續性、重播期限及照片／銀行對帳，刪除／停權、舊 LINE、已用邀請碼與送單不復活；不能證明完整的訂單或退款維持停賣及人工核對，沒有重複退款。抽查備份逾期刪除、私有照片期限、資料告知及每週額度檢查紀錄。
